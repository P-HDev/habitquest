🏆 HabitQuest

PWA de hábitos diários com conquistas no estilo Xbox: o usuário faz check-in todo dia e desbloqueia marcos (7, 21, 30… dias) por hábito. Fonte: HABITQUEST.md.

Stack React 18 + Vite + Tailwind · Express + TypeScript · SQLite Módulos 2 pacotes npm (packages/api, packages/web) Status MVP funcional; deploy de produção a definir (ver Estado) Node 20 nas imagens (packages/api/Dockerfile) Método XP + TDD + DDD

O projeto em 30 segundos

Cria o hábito

Nome, meta em dias (1–365) e ícone. Ao criar, a API gera as conquistas-marco do hábito.

Check-in do dia

POST /habits/:id/checkin: no máximo 1 por hábito por dia; desfazer com DELETE.

Conquistas avaliam

Após o check-in, EvaluateAchievements recalcula o progresso e desbloqueia o que atingiu a meta.

Lembretes

Um agendador (node-cron) manda Web Push às 08:00, 14:00 e 21:00 por padrão.

Dependências externas

  • Google OAuth (google-auth-library na API, @react-oauth/google na web): variáveis em packages/api/.env.example e packages/web/.env.example.
  • Web Push / VAPID: sem chaves VAPID o scheduler se desliga e só loga o aviso (packages/api/src/infrastructure/services/notification-scheduler.ts).

Pode / Não pode

Pode

  • Criar use case novo em packages/api/src/application/use-cases/ com teste antes.
  • Injetar repositório fake via createApp(deps) nos testes.
  • Usar getTestDatabase() (SQLite em memória) em teste de integração.
  • Documentar variável nova nos .env.example.

Não pode

  • Commitar segredo ou .env (.gitignore já ignora .env).
  • Depender do fallback habitquest-secret-dev de JWT_SECRET em produção (definir a variável).
  • Commitar arquivos *.db nem a pasta de dados do SQLite (ambos no .gitignore).
  • Pular os hooks (--no-verify) sem pedido explícito.
  • Colocar regra de negócio em controller ou rota; ela vive em packages/api/src/domain/ e packages/api/src/application/.

Dados pessoais (LGPD)

O sistema guarda e-mail, nome, avatar e hash de senha (packages/api/src/infrastructure/database/connection.ts). Política de retenção, exclusão de conta e consentimento: a definir (nenhuma fonte encontrada). Exemplos em testes e docs devem ser fictícios.

Como fazer

Rodar local

npm install
npm run api   # API em http://localhost:3000 (tsx watch)
npm run web   # Web em http://localhost:5173 (proxy /api → :3000)
cp packages/api/.env.example packages/api/.env   # preencher GOOGLE_CLIENT_ID, JWT_SECRET

Testar e validar

npm test            # api + web (também roda no pre-push)
npm run test:api
npm run test:web
npm run lint
npm run guia:check  # confere caminhos e âncoras deste guia

Criar uma feature (TDD)

  1. Teste vermelho em packages/api/tests/unit/ (domínio/use case) ou packages/api/tests/integration/ (endpoint); packages/web/tests/ para componentes.
  2. Entidade/VO em packages/api/src/domain/, use case em packages/api/src/application/use-cases/, repositório SQLite em packages/api/src/infrastructure/repositories/, rota em packages/api/src/presentation/routes/.
  3. Registrar a rota em packages/api/src/app.ts.
  4. Tabela nova ou coluna nova: editar runMigrations em packages/api/src/infrastructure/database/connection.ts (não há ferramenta de migration separada).

Criar uma tela

Página em packages/web/src/pages/, rota em packages/web/src/App.tsx, chamada HTTP em packages/web/src/services/ usando API_BASE.

Build / Docker

npm run build -w packages/api
npm run build -w packages/web
docker compose up --build   # api :3000, web :80 (docker-compose.yml)

Publicar

Há fly.toml (API, região gru, volume SQLite) e o commit 317e8a5 cita Fly.io + Vercel; HABITQUEST.md (EPIC 18) planeja Cloudflare. Procedimento oficial de publicação: a definir. Não há workflow de CI no repositório.

Healthcheck: GET /health (packages/api/src/presentation/routes/health.routes.ts).
